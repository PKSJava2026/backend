# Экспедиторская компания

Консольная информационная система на Java: заказчики оставляют заявки на перевозку, экспедитор заключает договоры с заказчиками и перевозчиками, изменение и расторжение договоров проходит по обоюдному согласию сторон. Данные хранятся в PostgreSQL, доступ через JDBC.

## Запуск

Нужны JDK 21+ и Docker.

```bash
docker compose up -d                    # PostgreSQL на порту 5434
./mvnw package                          # сборка (jar со всеми зависимостями)
java -jar cli/target/expedition.jar     # запуск
```

- Схема БД ([schema.sql](cli/src/main/resources/schema.sql)) создаётся автоматически при каждом запуске, скрипт идемпотентный.
- Параметры подключения: [db.properties](cli/src/main/resources/db.properties).
- Если в консоли Windows вместо кириллицы кракозябры: `chcp 65001`, затем `java -Dstdout.encoding=UTF-8 -jar cli/target/expedition.jar`.
- Пересоздать БД с нуля: `docker compose down && docker compose up -d`.

**Администратор по умолчанию:** логин `admin`, пароль `admin`. Заказчики и перевозчики регистрируются сами, экспедиторов назначает администратор.

## Возможности по ролям

| Роль          | Что может                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Заказчик      | создавать, просматривать, изменять, отменять и удалять заявки; видеть статус; подтверждать и отклонять предложенные договоры; предлагать изменение и расторжение; уведомления; оценивать услугу экспедитора (1-5)                                                                                                                                                  |
| Экспедитор    | все заявки (в том числе актуальные), смена статуса заявки; предлагать договоры с заказчиками и перевозчиками; договоры по ID; изменение и расторжение с подтверждением второй стороны; поиск, фильтрация, сортировка заявок и договоров; заявки перевозчиков о сотрудничестве; уведомления; оценка доставки; свой рейтинг; статистика, просмотр таблиц БД, экспорт |
| Перевозчик    | заявка о сотрудничестве; подтверждение договоров; изменение и расторжение; уведомления; свой рейтинг                                                                                                                                                                                                                                                               |
| Администратор | назначение и удаление экспедиторов; все функции экспедитора; статистика и экспорт                                                                                                                                                                                                                                                                                  |

Заключение, изменение и расторжение договора требуют согласия второй стороны: договор предлагает экспедитор, а запрос на изменение или расторжение может создать любая сторона, вторая принимает или отклоняет его. О каждом таком действии вторая сторона получает уведомление.

## Архитектура

Console UI → Service → Repository (JDBC) → PostgreSQL. SQL есть только в репозиториях, во всех запросах `PreparedStatement` и try-with-resources.

Maven multi-module (границы будущих сервисов):

| Модуль   | Содержимое                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `common` | `DatabaseManager`, исключения (`BusinessException`, `EntityNotFoundException`, `DatabaseException`, `ExportException`), чтение таблиц, экспорт в Excel и CSV |
| `auth`   | пользователи, роли, регистрация, вход (BCrypt), управление экспедиторами                                                                                     |
| `core`   | заявки, договоры, запросы на изменение, уведомления, оценки, заявки о сотрудничестве, статистика                                                             |
| `cli`    | консольное меню, `Main`, схема БД                                                                                                                            |

ООП: инкапсуляция (private-поля, Lombok), enum'ы (`Role`, `OrderStatus`, `ContractStatus`, `ChangeRequestStatus`, ...), интерфейс `Contract` с наследниками `CustomerContract` и `CarrierContract` (полиморфизм), общий `ContractRepository<T>` и `ContractService<T>`, коллекции и Stream API для поиска, фильтров и сортировки.

## База данных

8 связанных таблиц: `users`, `orders`, `cooperation_requests`, `customer_contracts`, `carrier_contracts`, `contract_change_requests`, `ratings`, `notifications`. Используются PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK и частичные уникальные индексы.

## Бизнес-правила

- Регистрация: корректные никнейм и email, пароль от 6 символов, уникальность никнейма (без учёта регистра) и email, самостоятельно можно стать только заказчиком или перевозчиком.
- Только администратор управляет экспедиторами; удалённый экспедитор не может войти.
- Заявка: обязательны груз и пункты, пункты не совпадают, вес и объём больше нуля, дата не в прошлом; изменять и удалять можно только заявку в статусе `NEW`.
- Переходы статусов заявки: `NEW → CONTRACTED → IN_TRANSIT → DELIVERED`, отмена до начала перевозки.
- Договор с заказчиком только по заявке в статусе `NEW` и только с её владельцем, с перевозчиком только по заявке в статусе `CONTRACTED` и только с активным перевозчиком; по заявке один открытый договор каждого вида.
- Цена больше нуля (до двух знаков после запятой), дата окончания не раньше начала.
- Изменить или расторгнуть можно только действующий договор; на один договор один открытый запрос; запрос подтверждает другая сторона, отозвать его может только автор.
- Оценка от 1 до 5, только по доставленной заявке, одна от автора на заявку.
- Перевозчик: не более одной необработанной заявки о сотрудничестве.

## Поиск, фильтрация, сортировка, статистика, экспорт

- Поиск, фильтр по статусу и периоду, сортировка (дата, статус, сумма или вес) для заявок и договоров: меню экспедитора.
- Статистика (9 показателей), просмотр таблиц БД, экспорт в `.xlsx` и CSV: «Статистика и экспорт данных» в меню экспедитора и администратора. Файлы сохраняются в папку `exports/`. Хеши паролей не выгружаются.
